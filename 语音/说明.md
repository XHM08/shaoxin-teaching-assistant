# 语音（讲稿配音）

邵新的「讲稿配音」能力把课件里每页的讲稿合成为 wav。全程只在本机跑，不上传。
它不自己实现语音合成，而是接一个本机服务：[GPT-SoVITS](https://github.com/RVC-BOSS/GPT-SoVITS)（MIT）。

## 为什么要分成两个进程

GPT-SoVITS 有自己的 Python 环境和约 5 GB 模型，它的依赖（`numba` / `funasr` /
`transformers` 都钉了版本）跟邵新这边合不到一个环境里。分开之后：

- 邵新照常能用；不配音的时候完全不需要开语音服务
- 服务没启动时，点「讲稿配音」会得到一句人话提示，而不是一段 `connection refused`

## 装（只装一次）

现在装在 `D:\projects\GPT-SoVITS`（2026-09-22 从 C 盘桌面搬过来的）。
它装在哪只写在 `语音/程序目录.txt` 一行里，搬地方只改那一个文件；见下面「搬家」一节。

**① 源码**：tag `20250606v2pro`。
注意本机 `github.com` 站点不通，但 `api.github.com` / `codeload.github.com` 通，
所以走 tarball 下：`curl -L -o src.tar.gz https://codeload.github.com/RVC-BOSS/GPT-SoVITS/tar.gz/refs/tags/20250606v2pro`

② 独立环境（用 uv，不碰系统里的 Python 3.12）：

```bash
uv venv --python 3.11 .venv
```

**③ torch**：本机是 RTX 5060 Laptop（Blackwell, sm_120），README 默认那套
`torch 2.5.1+cu124` 跑不了它，要用 cu128。轮子从交大镜像直链拉：
`https://mirror.sjtu.edu.cn/pytorch-wheels/cu128/torch-2.7.0%2Bcu128-cp311-cp311-win_amd64.whl`
（实测 26 MB/s，官方源只有 0.37 MB/s，差 45 倍。3.2 GB 的包从"一小时"变"三分钟"）
torchaudio 同源取出。

**④ 模型**：三个包走 `hf-mirror.com`（本机 `huggingface.co` 不通），解到：

| 包 | 大小 | 解到 |
|---|---|---|
| `pretrained_models.zip` | 4351 MB | `unzip -d GPT_SoVITS`（得到 `GPT_SoVITS/pretrained_models/`） |
| `G2PWModel.zip` | 561 MB | `unzip -d GPT_SoVITS/text`（中文前端要用） |
| `nltk_data.zip` | 9 MB | 解到仓库根 |

**⑤ 依赖**：只用"推理真正要到的"，不是整份 `requirements.txt`。踩过的坑都记在这：
- `jieba_fast` 在 PyPI 上只有源码包（任何 Python 版本都没轮子），而本机没有 MSVC 编译器。
  它在 `GPT_SoVITS/text/chinese2.py` 里是无条件 import（中文前端必需）。
  → 做法：在 `.venv/Lib/site-packages/jieba_fast/` 放一个纯 Python 同名替身，
  转出 `jieba` 的 `cut` / `lcut` / `tokenize` / `setLogLevel` 与 `jieba_fast.posseg`（转 `jieba.posseg`）。
  `jieba_fast` 本来就是 `jieba` 的 C 加速分支，API 同名、分词一致，就是慢些：
  我们一页讲稿就几行，差别可以忽略。这个替身只在 venv 里，不动系统、不进邵新仓库。
- `requirements.txt` 里那句 `--no-binary=opencc` 会强制源码编译，而 opencc 明明有 cp311 轮子 → 忽略它。
- 裁剪掉不装（不在推理这条路上）：`pyopenjtalk`（日语前端）、`funasr` / `faster-whisper`（打标用 ASR）、
  `modelscope`（降噪工具）、`tensorboard`（训练）。
- **补装**：`ffmpeg-python`（`TTS_infer_pack/TTS.py` 要）、`matplotlib`（AR 的 lr_scheduler 要）、
  `gradio`，以及把 `huggingface-hub` 钉到 `<1.0`。`transformers 4.50` 硬要求这个范围，
  不钉会报 `huggingface-hub>=0.26.0,<1.0 is required`。

一句话验证装好没（在 `样本` 目录下跑；它会读 `语音/程序目录.txt`，把目录、venv、关键模型文件、
以及那个 venv 能不能真导入依赖链一起验，搬盘之后尤其要跑）：

```bash
python 脚本/检查_语音安装.py
```

也可以只验依赖链本身（要把 `GPT_SoVITS` 也加进 sys.path，`AR` 是仓库里的目录不是 PyPI 包）：

```bash
.venv/Scripts/python.exe -c "import sys,os; now=os.getcwd(); sys.path += [now, os.path.join(now,'GPT_SoVITS')]; from GPT_SoVITS.TTS_infer_pack.TTS import TTS; print('OK')"
```

## 搬家（比如从 C 盘迁到 D 盘）

这套东西约 12 GB（`.venv` 约 6.8 GB + 模型约 4.7 GB）。搬完只需改一个文件：

1. 先关掉语音服务（那个黑窗口按 Ctrl+C）。文件被占着会搬不动
2. 把整个 `GPT-SoVITS` 文件夹搬到新位置（例子：本机就是这么搬的 → `D:\projects\GPT-SoVITS`）
3. 改 `语音/程序目录.txt` 里那一行（只这一行）
4. 在 `样本` 目录跑 `python 脚本/检查_语音安装.py`，全过就完事了
5. 要用时双击 `语音/启动语音服务.bat`（它是个双击外壳）

| 项 | 值 |
|---|---|
| 总大小 | 11.89 GB |
| 文件数 / 目录数 | 39681 / 3953 |
| `.venv/Scripts/python.exe` | 有（靠 `pyvenv.cfg` 找环境） |
| `GPT_SoVITS/pretrained_models/s2G488k.pth` | 101.1 MB |
| `…/s1bert25hz-2kh-longer-epoch=68e-step=50232.ckpt` | 147.9 MB |
| `…/gsv-v2final-pretrained/s2G2333k.pth` | 101.1 MB |
| `…/chinese-hubert-base/pytorch_model.bin` | 180.1 MB |
| `…/chinese-roberta-wwm-ext-large/pytorch_model.bin` | 621.1 MB |
| `GPT_SoVITS/text/G2PWModel/g2pW.onnx` | 605.8 MB |

完整清单在 `脚本/检查_语音安装.py` 里（它验的就是上表那几件）；下次搬家照这几个数对一遍就够。
**说明一下它能证明什么、不能证明什么**：
能证明"没少搬、没截断"（总量 + 关键文件大小都对得上，而且搬完真的合成出了音频）；
不能做逐字节比对：C 盘原件已删、模型压缩包也清了，没有哈希基线，
所以"完全没变"这件事只有功能性证据（能跑通），没有哈希级证据。

### 搬盘后哪些东西会坏、哪些不会

- **不会坏的**：`pyvenv.cfg` 指的是 uv 自己的 Python（在 `AppData` 里，搬到哪儿都找得到）；
  GPT-SoVITS 自己的代码用的是相对路径（`GPT_SoVITS/pretrained_models/…` 都是相对当前目录）
- **会坏的**：`.venv/Scripts/*.exe` 那些启动器（`uvicorn.exe` / `accelerate.exe` 之类）内嵌了
  venv 的旧绝对路径，搬完就失效。我们不用它们：启动只调 `.venv\Scripts\python.exe api_v2.py`
  （`python.exe` 靠 `pyvenv.cfg` 找环境，不受影响）。同理 `.venv/Scripts/activate` 里的
  `VIRTUAL_ENV` 也是旧路径，别用它激活，直接给 python.exe 绝对路径最稳。
- **路径里最好别夹中文**：cmd 那套编码坑很深（`.bat` 里已经 `chcp 65001`，纯英文路径最省事）

## 用

1. 双击 `语音/启动语音服务.bat`（它只是个双击外壳），等它打印监听端口（黑窗口别关）。
   一般 20 秒左右起来，慢的时候一分多钟（同一台机器实测过 20 秒与 65 秒两次）；
   等久了别急着重启，先看那个黑窗口里有没有报错
2. 在邵新里先「PPT 生成」造一份课件，再点 「讲稿配音」，填课件文件名
3. wav 落在 `课件输出/<课件名>_配音/第N页.wav`。网页播放器能直接播，WPS 也能贴到单页上

> 要改启动行为（读位置、校验文件、取端口、拉起服务），改的是 `语音/启动语音服务.py`，不是那个 `.bat`。
> 逻辑后来从 .bat 挪到了 .py（.bat 里读路径会碰上 cmd 的编码怪毛病，见 `地基/语音.读程序目录()` 的说明），
> 现在 `.bat` 只剩“找 python → 调 .py → pause”。只改 .bat 是不会生效的：
> 本项目在“改了代码不生效”上已栽过几次（跑着的旧进程、双击外壳）。

实测（2026-09-22，RTX 5060 Laptop）：4 页讲稿 → 4 个 wav，32000 Hz 单声道 16 bit，
每页时长与字数成比例（约 4.2 字/秒），无静音段。
**耗时不是一个数，按状态分**：

| 时机 | 4 页课件的配音耗时 |
|---|---|
| 热身后（服务已经在跑、合成过一次） | 约 20 秒（≈5 秒/页） ← 老师平时遇到的就是这个 |
| 服务刚启动后第一次 | 62 ～ 181 秒（要把 5 GB 权重加载进显存；测到过 62 秒，也测到过 181 秒） |
| 跑真模型那次（模型调用 + 配音整程） | 87 秒（其中配音 77 秒） |

端口如果不是 9880，改 `配置.json` 里的 `语音.地址` 即可（默认 `http://127.0.0.1:9880`）。
